# M5 — Nearby Stops + Bus Arrivals screens

**Status:** ⬜ Pending
**Depends on:** M3 (queries/store), M2 (arrivals), M4 (favorites)

> **Parity gate starts here:** each feature is done only when its XCUITest passes **and** its parity
> screenshot is signed off against the running Flutter app (tracked in `../parity/`). Signed-off
> screenshots become snapshot baselines.

## Goal

The two core rider screens: the location-driven Nearby Stops list and the live Bus Arrivals screen
(with crowding/Load, polling, pull-to-refresh, not-in-operation, and favorite toggling).

## Scope

### Location
- [ ] CoreLocation service (`CLLocationManager`): permission flow, current position, position stream
      (5 m filter), `distance(from:)`. Ref: `lib/src/user_location/location_service.dart`.

### Nearby Stops (Tab 0)
- [ ] `BusStopsService.getNearbyBusStops`: all cached stops → distance → **within 500 m** → sorted
      ascending. Ref: `bus_stops_service.dart`.
- [ ] Stop card: description + `code | roadName` + distance + chevron; tap → Arrivals. Ref:
      `bus_stop_card/*`, `bus_stop_distance.dart`.
- [ ] Loading states: DB-init download progress (from M3), then "Looking for nearby bus stops...".
      Ref: `bus_stop_list_loading.dart`.

### Bus Arrivals
- [ ] `BusArrivalsService.getBusArrivals` (port `bus_arrivals_service.dart`): fetch live arrivals;
      **reconstruct not-in-operation services** by diffing cached routes for the stop vs. the API
      result; enrich destination names from cached stops; sort by numeric service number.
- [ ] Screen (port `bus_arrival_list_screen.dart`, `bus_arrival_card/*`): stop header, **Load legend**
      (Seats Avail. / Standing Avail. / Limited Standing), arrival cards (service no + "to
      {destination}", three times separated by arrows, **colored Load underline**, favorite toggle),
      **auto-poll + pull-to-refresh**, "Not In Operation" state, optional "Last Update" line gated by
      Remote Config (M1b).
- [ ] Error + Retry view (parity with `error_display.dart`).
- [ ] Navigate Arrivals → Bus Service details (full screen) on in-service header tap (screen lands M6).

## Verification

- Side-by-side with the Flutter app on the same stops: arrival times, Load colors, order, and
  not-in-operation entries match.
- XCUITests (stub mode, seeded store + stubbed arrivals + fixed clock): nearby list renders & sorts;
  arrivals legend + card states + Load colors; favorite toggle persists; pull-to-refresh.
- Parity screenshots signed off for: nearby list, arrivals (in-service), arrivals (not-in-operation),
  each Load color.
