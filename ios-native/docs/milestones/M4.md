# M4 — Favorites / UserDefaults migration shim

**Status:** ⬜ Pending
**Depends on:** M3

## Goal

Because we ship as an **update to the same bundle id**, existing users' data lives in the Flutter
`UserDefaults` store. On first launch of the SwiftUI build we must read it so **nobody loses their
favorites or settings**. This is the single highest-risk correctness item in the rewrite.

## Scope

- [ ] One-time, **idempotent** migration (guarded by a `didMigrate` flag) that runs before any
      favorites read.
- [ ] Read existing Flutter values from `UserDefaults.standard` under the **`flutter.`-prefixed** keys:
  - [ ] `flutter.favouriteServiceNoKey` — list of `busStopCode~serviceNo` (delimiter `~`). Note the
        British spelling `favourite`.
  - [ ] `flutter.favouriteBusStopsKey` — legacy stop-level favorites.
  - [ ] `flutter.bottomBarIndex`, `flutter.firstLaunchKey`, `flutter.launchCountKey`,
        `flutter.refreshDateKey`.
  Ref: `lib/src/local_storage/local_storage_keys.dart`, `local_storage_service.dart`.
- [ ] Port **`handleLegacyFavorites()`**: convert legacy stop-level favorites to `code~serviceNo`
      using cached routes (needs M3), then clear the legacy key. Ref: `bus_arrivals_service.dart`.
- [ ] Native favorites store (`@Observable`) backed by `UserDefaults`: list, `isFavorite`, toggle —
      same `busStopCode~serviceNo` format so a re-migration is a no-op.
- [ ] **Verify the on-disk encoding against a real build before finalizing the reader**: install the
      current App Store/TestFlight app, add favorites, dump the container `UserDefaults`, and confirm
      how `shared_preferences` stores the string list (plain `[String]` vs. type-prefixed entries).
      Adjust the reader to match what's actually on disk.

## Verification

- A device/simulator seeded with the current Flutter app's `UserDefaults` shows the **same favorites**
  after upgrade-in-place.
- Legacy stop-level favorites convert correctly and the legacy key is removed.
- Migration is idempotent across repeated launches (no duplicates, no loss).
- Unit tests cover the parser against captured real-world `UserDefaults` payloads.
